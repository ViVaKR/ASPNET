# Contracts

### 📦 프로토 계약서 프로젝트의 필수 삼총사 분석

1. **`Google.Protobuf`**
* **정체:** Protobuf 메시지(데이터 구조)를 직렬화(Serialization)/역직렬화(Deserialization)하고 메모리에 올리기 위해 **반드시 필요한 런타임 라이브러리**
* **필요성:** 생성된 C# 코드(`chat.pb.cs` 등)가 실제로 동작하려면 이 라이브러리의 클래스들을 상속받고 쓰기 때문에 앱 실행 시에도 무조건 필요


2. **`Grpc.Core.Api`**
* **정체:** gRPC 통신에 필요한 핵심 인터페이스와 API 규격(채널, 서버, 클라이언트 추상화 등)을 담고 있는 **공통 계약 라이브러리**
* **필요성:** gRPC 서비스와 상호작용하기 위한 표준 껍데기(인터페이스)를 제공해주기 때문에 컴파일 타임과 런타임 모두에 필수.


3. **`Grpc.Tools`**
* **정체:** **빌드 타임(Build-time) 전용 도구**야.
* **핵심 특징 (`PrivateAssets="All"`):** 뒤에 붙은 옵션 보이지? 이 패키지는 내 코드가 다른 프로젝트에 참조될 때 쓸데없이 딸려 들어가지 않도록(전파되지 않도록) 빌드할 때만 몰래 쓰고 빠지는 **컴파일러(protoc)와 MSBuild 툴킷**
* **필요성:** 빌드할 때 `.proto` 파일을 읽어서 C# 소스 코드(`.cs`)로 싹 변환해 주는 마법을 부리는 주역이지. 얘가 없으면 `<Protobuf>` 태그를 읽을 줄 몰라서 빌드가 터짐


4. **`<Protobuf Include="..."/>`**
* 이건 패키지가 아니라, `Grpc.Tools`가 제공하는 빌드 엔진에게 "이 `.proto` 파일을 컴파일해서 C# 코드로 만들어라"고 명령을 내리는 MSBuild 아이템 태그야.



---

### 💡 결론

* **중복되는 것은 전혀 없습니다.**
* `Google.Protobuf`(데이터 처리), `Grpc.Core.Api`(gRPC 규격), `Grpc.Tools`(컴파일러 및 빌드 도구)가 각각 **데이터 / 통신 / 빌드**라는 전혀 다른 영역을 완벽하게 분담하고 있기 때문에, 계약서 프로젝트(`Contracts`)에서는 이 세트가 바로 **국룰 정석 구성**이야.
